## Stage (c) Research — DONE

Confirmed the technical approach and its one real landmine:

- **Pose detection**: MediaPipe Tasks Vision `PoseLandmarker` (`@mediapipe/tasks-vision@1.0.1`,
  Apache-2.0), `pose_landmarker_lite` model (`.task` bundle, ~5.5MB, Apache-2.0 per the official
  BlazePose GHUM 3D model card — redistributable, no non-commercial restriction). Both the JS
  runtime and the wasm/model assets can be vendored (downloaded once, committed as static
  self-hosted assets) — Apache-2.0 explicitly permits this provided the license/attribution is
  preserved. `FilesetResolver.forVisionTasks()` and `PoseLandmarker.createFromOptions()` both
  accept same-origin relative paths, so no CDN dependency at runtime. Single-image detection is
  `detect()` (IMAGE mode) returning 33 normalized landmarks with x/y/z/visibility.
- **The landmine**: current `@mediapipe/tasks-vision` builds (through the current 1.0.1) contain
  an internal, undocumented telemetry beacon that attempts to phone home to Google's logging
  endpoint regardless of self-hosting the assets — open, unresolved upstream issues (#6291,
  #4991), no official opt-out. That's a direct conflict with PRINCIPLES ("no third-party
  scripts," "no trackers," "every asset served from our own deploy"). **Mitigation, decided
  here**: ship a strict same-origin CSP (`connect-src 'self'`, plus the narrowest other
  directives the app needs) via a `<meta http-equiv="Content-Security-Policy">` tag. This makes
  "zero network calls leave the browser" a property the *browser itself* enforces, not something
  that depends on correctly patching a minified vendored file — verifiable and robust, and it's
  the adversarial breaker's job later this run to confirm zero non-origin requests with a
  network-log check. This is a deviation worth recording as a durable technique: any future app
  vendoring a Google/Meta/etc. ML library should assume telemetry-by-default and enforce CSP
  rather than trust vendoring alone. *(Follow-up for docs: worth adding a line to
  ARCHITECTURE or PRINCIPLES about this pattern — not done in this commit, flagging for the
  next session or a dedicated docs pass.)*
- **Garment cutout, no ML needed**: e-commerce product photos are near-universally shot on
  plain/near-white backgrounds. A corner-sampled flood-fill (sample the four corner pixels,
  remove near-matching background color with a feathered edge) is a classical, zero-dependency
  technique that handles the actual target use case (a screenshot from a shop) without needing
  any segmentation model or bundled dataset.
- **The warp**: piecewise-affine mesh warp (split the garment quad into two triangles, solve the
  3-point affine matrix per triangle, `ctx.transform` + clip + `drawImage`) is well-understood
  classical graphics, implementable from scratch in vanilla canvas with zero libraries. It
  deliberately cannot fake fabric drape or occlusion — the plan is to render the result as an
  honestly-labeled stylized/semi-transparent overlay, never claiming photorealism, which sidesteps
  exactly the failure modes that make full photoreal try-on hard.
